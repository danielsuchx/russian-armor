# Russian Armour

Нативное приложение для строки меню macOS, которое ставит Claude на паузу, если страна
выхода не подтверждена или изменилась. Работает с VPN на Mac и на роутере, без Network
Extension и без прав администратора.

## Как работает защита

- обнаруженные Claude Desktop, Claude Code и их дочерние процессы ставятся на паузу до подтверждения страны; новые процессы обнаруживаются опросом и могут успеть отправить данные;
- приложение отслеживает системные уведомления об изменениях маршрута, интерфейса и адреса; реакция не мгновенная;
- внешний IP считается подтверждённым, только если ipwho.is и IPinfo увидели одинаковый адрес; страну определяет основной сервис ipwho.is;
- плановая проверка выполняется фоново раз в минуту;
- плановая фоновая проверка не приостанавливает уже подтверждённую сессию Claude;
- если страна совпадает с разрешённой, остановленные процессы продолжают работу;
- при несовпадении, ошибке проверки, смене сети или сне Claude снова ставится на паузу;
- проверка PID, UID и времени запуска защищает от отправки сигнала переиспользованному PID.

При первом запуске включите VPN и один раз подтвердите найденную страну. В дальнейшем проверка
выполняется автоматически, но не подтверждает маршрут отдельных соединений Claude. Сохраняется
только код разрешённой страны; внешний IP остаётся в памяти и не записывается в журнал.

Подробный контракт и ограничения: [docs/protection.md](docs/protection.md).

## Требования и запуск

- macOS 13 или новее;
- Xcode с поддержкой Swift 5.9 или новее для сборки из исходников.

```bash
bash scripts/build-app.sh
open "dist/Russian Armour.app"
```

Приложение работает в строке меню и не отображается в Dock. Левый клик по щиту открывает
панель, правый — системное меню. При обычном выходе Russian Armour продолжает процессы,
которые остановило само.

Локальная сборка имеет ad-hoc подпись. Для запуска самой процессной защиты платная Apple
Developer Program не требуется. Developer ID и notarization полезны для удобного публичного
распространения без предупреждений Gatekeeper, но не участвуют в механизме паузы.
После загрузки такой сборки из GitHub Gatekeeper её заблокирует: пользователь должен сначала
попытаться её открыть, затем выбрать «Системные настройки → Конфиденциальность и безопасность →
Всё равно открыть». Это штатный [сценарий Apple](https://support.apple.com/102445), но он хуже по доверию и UX, чем
подписанный и нотаризованный релиз.

## Настройка

В настройках можно:

- указать, где работает VPN — на роутере или на этом Mac;
- сбросить разрешённую страну и выбрать её заново;
- включить отображение локальных туннелей и запись сетевых событий.

Оба сервиса получают IP своего запроса и возвращают оценку страны. Сессии эфемерные,
перенаправления запрещены, каждый ответ ограничен 4 КиБ, проверка TLS не отключается. При ошибке
или расхождении ответов Claude остаётся на паузе.

## Какие процессы распознаются

- Claude Desktop по bundle identifier `com.anthropic.claudefordesktop`;
- native Claude Code по имени исполняемого файла `claude` или `claude-code`;
- npm-версия Claude Code в `node`, `bun` или `deno` по маркеру `@anthropic-ai/claude-code` в аргументах;
- всё обнаруженное дерево их дочерних процессов.

Аргументы читаются только у известных JavaScript-интерпретаторов, не сохраняются и не показываются в UI.
Программы другого пользователя и процессы root не изменяются.

## Граница защиты

Это process-level kill switch. Между сменой маршрута и реакцией приложения возможен короткий
промежуток. Для гарантии «ни одного пакета мимо VPN» включите также kill switch VPN или
блокировку прямого выхода на роутере. Отдельный watchdog следит за основным процессом: при аварии
ставит Claude на паузу и перезапускает Russian Armour; при обычном выходе приложение не возвращается.

## Диагностика

Окно «Сетевые соединения» по явной кнопке показывает снимок TCP/UDP-сокетов процессов
текущего пользователя через публичные API `libproc`. Содержимое TLS, токены, cookie и данные
запросов не читаются. Снимок хранится только в памяти.

## Проверка

```bash
swift test
```

Последний прогон: 164 теста, 7 пропущено, 0 ошибок. Тесты процессной защиты используют
синтетические PID и не отправляют сигналы реальным приложениям. Ошибки watchdog
отслеживаются и логируются в журнал событий.

Старый экспериментальный Network Extension и адаптер Xkeen сохранены в исходниках для
исследований, но основной пользовательский сценарий их не устанавливает.
