# Защита Claude без VPN для всего Mac

Основной экран защиты относится к Claude Desktop, распознанному Claude Code и
отдельному профилю браузера Claude. Существующий PF/WireGuard kill switch всего
компьютера остаётся отдельной настройкой в «Дополнительно · VPN для всего Mac».
Процессная защита работает и без него.

## Claude в браузере

Кнопка «Открыть Claude в отдельном браузере» запускает Chrome, Brave, Chromium или
Edge с отдельным каталогом данных `~/Library/Application Support/Russian Armor/Claude Browser`.
Профиль создаётся с правами 0700. Существующие профили, расширения, cookies,
системные политики браузеров и настройки сети не редактируются.

Каждый запуск передаёт `--force-webrtc-ip-handling-policy=disable_non_proxied_udp`,
`--webrtc-ip-handling-policy=disable_non_proxied_udp`, `--disable-quic`,
`--dns-over-https-mode=secure` и шаблон DoH Cloudflare. Secure DoH не разрешает
обычный DNS-fallback в этом профиле. Это ограничивает прямой WebRTC/UDP в этом
профиле; TCP/TURN и сам DoH могут использовать обычный маршрут HTTP. Эти флаги проверены на установленном Google Chrome:
обычный тестовый профиль получил ICE host/srflx, защищённый — пустой список.

Дерево процессов только этого профиля включается в существующий контроль Claude
и закрывается при выходе Russian Armor. Остальные профили того же браузера
не включаются в него. Первое обнаружение нового процесса выполняется опросом;
процессная пауза не равнозначна атомарной сетевой блокировке.

DoH скрывает имена запрашиваемых доменов от локального DNS-провайдера, но сам
провайдер DoH (Cloudflare) их видит. Соединение к DoH следует правилам VPN/Xkeen;
добавьте домен DoH в немецкий маршрут, если он тоже должен выходить через Германию.

Используйте именно эту кнопку, а не вкладку Claude в личном профиле браузера.
Сайт не получает защиту WebRTC от одного факта запуска Russian Armor.

## Claude Desktop и сетевой фильтр

Обычные флаги Chrome не считаются доказательством ограничения WebRTC в Electron.
Поэтому при запуске Claude Desktop кнопкой Russian Armor передаются те же
Chromium-политики: secure DoH без plaintext-fallback, запрет QUIC и запрет
непроксированного WebRTC UDP. Это применяется только к новому экземпляру,
запущенному приложением; уже работающий Claude нужно закрыть и запустить заново.

Этот вариант не требует платной Apple Developer подписки. Без неё системный
Network Extension не устанавливается, поэтому фильтрация на уровне ядра остаётся
недоступной; политики запуска и отдельный браузерный профиль продолжают работать.
Новый `NEFilterDataProvider` блокирует все UDP-сокеты распознанных процессов Claude
(включая произвольные порты STUN/TURN и QUIC). TCP разрешается отдельной короткой
политикой Desktop/Code; политика истекает через 4 секунды без обновления.
Разрешение проверяется на каждом блоке данных, а активные TCP-потоки отзываются
при запрете либо истечении политики. Содержимое данных не анализируется и не сохраняется.

Для Claude Desktop и его подписанных helpers источник определяется из системного
аудит-токена и идентификатора подписи Anthropic. Распознанные процессы Code,
дочерние процессы и отдельный браузер дополнительно передаются из каталога GUI
с PID и временем создания процесса. При выходе процесса прежний PID не даёт
разрешения новому владельцу. При первом соединении фильтр дополнительно проверяет
живую цепочку родителей, не ожидая следующего опроса GUI, и запоминает источник
до завершения процесса. Если дочерний процесс успел потерять всю распознаваемую
цепочку родителей до первого соединения и не попал в каталог GUI, его происхождение
не гарантируется; это не заявляется как полная изоляция произвольного кода.
Без доступного audit-токена фильтр не может приписать соединение Claude и не
блокирует чужие приложения. Запрет UDP не скрывает все сведения о локальных
интерфейсах и не отключает сам JavaScript API WebRTC.

XPC принимает политику только от подписанного `app.russian-armor.desktop` той же
Apple team. Каждое подключение ограничивается своим UID. Отчёты фильтра не содержат
URL, адресов, ключей или содержимого чатов. При включённом фильтре его отсутствие
или устаревший ответ дополнительно закрывает допуск процессов в GUI.

Фильтр не меняет PF, маршруты, DNS и настройки российских приложений. Разрешение
TCP не означает принудительное направление этого соединения в VPN: сам по себе
content filter не перенаправляет трафик. При Xkeen
выходы по доменам по-прежнему определяет роутер. Проверка общего внешнего IP
Russian Armor не доказывает выход отдельного домена Claude через Xkeen;
необходима проверка правил и отказа туннеля на самом роутере.

Для требования «все соединения Claude и его дочерних процессов только через VPN»
нужны принудительное направление в отдельный туннель/прокси и запрет прямого
выхода при его недоступности. Этих свойств текущий content filter не обеспечивает;
одна его установка не завершает такую защиту. Правила Xkeen только по доменам
не охватывают произвольные адреса, к которым обращаются дочерние процессы.

## Сборка и активация

Для фильтра нужны подписанный host, System Extension и provisioning profiles
с `content-filter-provider-systemextension`. Ad-hoc подпись их не заменяет.
Обычная сборка без этих профилей явно показывает «WebRTC Desktop · фильтр не
подтверждён» и не выдаёт компиляцию за активную системную защиту.

```sh
# Компиляция без установки и без изменения сети:
bash scripts/build-claude-filter.sh --unsigned

# После входа в Apple Developer в Xcode → Settings → Accounts:
ARMOR_FILTER_TEAM_ID=YOUR_TEAM_ID ARMOR_SIGNING_IDENTITY='Apple Development' bash scripts/build-app.sh release native
```

Запускайте подписанное приложение из `/Applications`. При наличии встроенного
фильтра Russian Armor запрашивает его активацию автоматически; macOS требует
разрешить расширение и фильтрацию в системном окне. Установка включает ограничение
UDP по умолчанию, без строгого VPN. До свежего XPC-ответа статус не считается рабочим.
Отключить установленный фильтр можно в системных настройках сетевых расширений.

Во время этой реализации автоматическое получение профиля остановилось на
отклонённом входе Apple в Xcode. Неподписанный фильтр успешно компилируется, но
не установлен и не проверен в живой системе. Политика проверяется unit-тестами;
проверка реальных потоков после разрешения macOS всё ещё необходима.
