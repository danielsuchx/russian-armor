# Экспериментальный kill switch для всего Mac

> **Это код экспериментального режима, а не проверенный production firewall.**
> Служба не устанавливается при сборке приложения. В этой разработке ни служба,
> ни правила на рабочем Mac не включались. До использования нужна отдельная
> macOS VM с локальной консолью, тестовым VPN и возможностью восстановления.
> Зелёные unit-тесты не доказывают отсутствие сетевых утечек.

## Что добавлено

`ArmorFirewall` — отдельный исполняемый файл и root LaunchDaemon. GUI остаётся
обычным пользовательским приложением, читает только root-owned status.json и не
передаёт произвольные команды, пути или PF-текст привилегированной службе.
Процессная пауза Claude остаётся отдельным дополнительным механизмом.

Режим рассчитан **на весь Mac и локальный VPN с utun**. VPN на роутере,
только-локальный HTTP/SOCKS-прокси и выборочная фильтрация исключительно Claude
не поддерживаются. Нужны подписанный владелец utun, IPv4 в туннеле, физический
интерфейс `enN` и заранее известные числовые IPv4 серверов VPN.

Служба независимо проверяет владельца (Team ID / signing identifier, PID,
время запуска, интерфейс, адреса), делает TLS-запрос ipwho.is через requiredInterface,
запрашивает у IPinfo именно полученный IP и применяет собственный allowlist.
Страну для разрешения определяет ipwho.is; расхождение с IPinfo остаётся
диагностикой, а страна из второго ответа, явно внесённая в запреты, блокирует доступ.
При временном 429/5xx IPinfo используется повторная проверка ipwho.is через тот же
туннель, но закреплённый IP выхода и WireGuard-handshake остаются обязательными.
Запреты имеют приоритет; дополнительный allowlist
IP/CIDR относится к публичному выходу проверки, не к назначениям приложений.
После ошибки, смены туннеля или просрочки снова нужны три успеха с интервалом
не менее двух секунд. Допуск живой службы ограничен 30 секундами от успешной
проверки; плановая проверка начинается через 10 секунд после успеха.

## Сетевой контракт

Первый filtering anchor в `/etc/pf.conf` — `app.russian-armor`, с `quick`.
В нём все правила `pass` используют `no state`; последний — `block drop quick all`.
Допуск обычного трафика связан с точным utun и его числовыми source addresses,
а не просто с наличием любого VPN. На физическом интерфейсе нет общего pass.
TCP и UDP/QUIC не получают обходного пути через обычную сеть. IPv6 пока
блокируется полностью, в том числе внутри туннеля: его страна отдельно не проверяется.

Исключения остаются даже в состоянии blocked:

- loopback `lo0`;
- DHCPv4: клиентский порт 68 и серверный порт 67 на выбранном физическом интерфейсе;
- точные IPv4/протокол/порт VPN-серверов на выбранном физическом интерфейсе;
- во время проверки: root TCP/443 через подтверждённый utun только к числовым
  адресам двух проверочных сервисов и их входящие ответы.

**Исключения VPN — не идентификация процесса.** Любая программа может послать
пакет на разрешённый IP/порт VPN-сервера. DHCP также не аутентифицируется.
Это не режим «вообще ни одного пакета вне utun». Общего разрешения для DNS,
локальной сети, captive portal, NTP, APNs или IPv6 bootstrap нет. Эти функции
могут перестать работать. ARP не является IP-трафиком и PF так не фильтруется.

Фиксированные IP проверочных сервисов исключают зависимость bootstrap от DNS.
TLS SNI и проверка сертификата используют исходное имя сервиса, а не числовой IP.
Редиректы, обход TLS-проверки и fallback в URLSession не используются.
Смена адресов сервиса требует явного обновления системной конфигурации.

При включении **глобально сбрасывается таблица PF states**, включая чужие
существующие соединения и NAT states. Это намеренный разрыв соединений всего
Mac: старые floating states иначе могут обойти новые правила. Служба не вызывает
`pfctl -d` и `pfctl -F all`.

## Установка: только после VM-проверки

Все команды сборки выполнять обычным пользователем, **не через sudo**:

```sh
swift build -c release
.build/release/ArmorFirewall example > firewall.json
.build/release/ArmorFirewall tunnels
```

В примере все `192.0.2.x` — **TEST-NET заглушки**, не реальные серверы.
Нельзя включать этот пример без замены полей:

- `physicalInterface`: действительный интерфейс доступа, например `en0`;
- `vpnOwnerKey`: точный `TEAMID/signing.identifier` из команды `tunnels`;
- `endpoints`: все необходимые серверы VPN, точные IP/порт/`tcp` или `udp`;
- `probeAddresses`: актуальные IPv4 `ipwho.is` и `ipinfo.io`, полученные заранее
  из доверенной конфигурации/резолвера и проверенные для этого VPN;
- `rules`: явные разрешённые страны, запреты, при необходимости IP/CIDR.

Системная политика **не синхронизируется автоматически с профилем в GUI**.
Это сознательная граница: изменение пользовательских настроек не расширяет
системный firewall. Для смены политики: явный disable, uninstall, install новой
конфигурации и новое enable. Промежуток выключения не защищён.

Без прав root и без изменения сети можно проверить формат и увидеть blocked rules:

```sh
.build/release/ArmorFirewall validate firewall.json
.build/release/ArmorFirewall render firewall.json
```

Установка — отдельное действие администратора; после неё служба **выключена**:

```sh
sudo .build/release/ArmorFirewall install "$PWD/firewall.json"
```

Установленные файлы:

- `/Library/PrivilegedHelperTools/app.russian-armor.firewall` — root:wheel, 0755;
- `/Library/LaunchDaemons/app.russian-armor.firewall.plist` — root:wheel, 0644;
- `/Library/Application Support/Russian Armor Firewall/` — root-owned;
- `configuration.json`, arm-marker и резервная копия — 0600;
- `status.json` — 0644, без публичного IP и содержимого сокетов Claude.

Пути записи фиксированы; проверяются владельцы/права каталогов, отсутствие symlink
и hardlink у файлов, тип и размер. Запись — через exclusive temporary file,
fsync и rename. Управляющие операции сериализуются flock. Служба не запускает shell.
Локальная сборка не является подписанным и нотарифицированным установщиком.
Установка root-бинарника допустима только из доверенного проверенного checkout.

**До enable держите открытой локальную Terminal-консоль и подготовьте disable.**
Не делайте это через SSH, удалённый рабочий стол или активную рабочую сессию:

```sh
sudo /Library/PrivilegedHelperTools/app.russian-armor.firewall enable --acknowledge-whole-mac-outage
/Library/PrivilegedHelperTools/app.russian-armor.firewall status
```

Автоматически поддерживается только штатная конфигурация PF с Apple anchors.
Нестандартные disk/live filtering rules и активные NAT/rdr translations
отклоняются, а не переписываются: translation с `pass` может обойти filtering.
При этом перезагрузка главного ruleset всё равно может конфликтовать с динамическими
Apple/VPN anchors, Internet Sharing и другим сетевым ПО: их совместимость
должна быть проверена отдельно. В каталоге службы сохраняется исходный pf.conf.

Если файлы установились, но `launchctl bootstrap` завершился ошибкой, операция
не считается успешной. Повторить запуск можно явно командой
`sudo /Library/PrivilegedHelperTools/app.russian-armor.firewall start`.
Она не меняет armed/disabled выбор. Ошибка запуска не разрешает включать режим
без выяснения причины.

## Выключение и восстановление

Закрытие GUI, ошибка HTTP, отсутствие VPN и завершение daemon **не снимают** правила.
Выключение выполняется явно:

```sh
sudo /Library/PrivilegedHelperTools/app.russian-armor.firewall disable
```

Исходный pf.conf восстанавливается, затем освобождается только собственный
PF enable-reference через `-X`, без глобального `pfctl -d`. Другие владельцы PF
не отключаются. Токен хранится с идентификатором загрузки; после reboot берётся
новый. Если процесс упал между `-E` и записью токена, возможен лишний enable-reference
до reboot — это не открывает сеть, но может оставить PF включённым после disable.
Если после включения администратор изменил ruleset, автоматическое восстановление
откажется его затирать. Не используйте `pfctl -d` как штатный способ отключения.

Удаление службы после восстановления доступа:

```sh
sudo /Library/PrivilegedHelperTools/app.russian-armor.firewall uninstall
```

При прерванном enable arm-marker и backup позволяют службе повторить закрытие
после перезапуска. При неуспешном включении нельзя считать защиту работающей:
нужны status, локальная консоль и проверка PF. На диске anchor содержит только
blocked-правила; разрешение туннеля загружается только в live ruleset.

## Границы гарантий

- **До запуска службы при загрузке macOS нет доказанной блокировки.** launchd
  не даёт здесь подтверждения «ни одного пакета с первого момента boot».
- Если daemon аварийно завершён, PF сохраняет последний ruleset и прямой выход
  остаётся запрещён. Но открытый в нём старый utun может оставаться разрешённым
  до перезапуска daemon: **PF не исполняет 30-секундный географический lease сам**.
  KeepAlive — попытка перезапуска, а не доказательство мгновенного восстановления.
- Повторное использование того же имени utun и тех же адресов до реакции службы
  не исключено полностью. При работающей службе смена владельца отзывает допуск.
- Проверка страны выполняется по IPv4. IPv6 полностью заблокирован, в том числе
  через VPN. IPv6-only сервисы в этом режиме не работают; для поддержки нужна
  отдельная проверка IPv6 egress, а не перенос доверия с IPv4.
- Любой администратор/root может отключить PF, сменить правила или бинарник.
  Другой привилегированный VPN/firewall также может конфликтовать с этим режимом.
- Свежий status — сообщение службы, не независимый захват пакетов. Через 6 секунд
  без heartbeat GUI показывает «защита не подтверждена», а не старый зелёный статус.
- Работоспособность VPN bootstrap, актуальность server/probe IP и фактическая
  фильтрация требуют теста с конкретным VPN. Unit-тест этого не доказывает.

## Обязательная VM-проверка перед рабочим использованием

| Сценарий | Что проверить внешним наблюдением и локальной консолью |
| --- | --- |
| Новое включение при открытых TCP/UDP | Старые states сброшены; новых прямых соединений нет |
| VPN отсутствует/оборван | На физическом интерфейсе только заявленные исключения |
| VPN восстановлен | Только выбранный utun; три успешные проверки до допуска |
| ipwho.is даёт RU/неизвестную страну/ошибку или вторая страна входит в запреты | Пользовательский трафик блокируется |
| IPv6 / QUIC / DNS | Не обходят правило через физический интерфейс |
| Kill GUI, kill daemon, reboot, sleep/wake | Сверить реальные окна, persistent blocked anchor и восстановление |
| Повторное имя utun / другой VPN | Не переносить разрешение без новой проверки |
| Нестандартный PF / другой firewall | Отказ или честный broken, без затирания чужих правил |
| Disable/uninstall, прерывание enable | Восстановление исходной конфигурации и работоспособности сети |

Пока этот протокол не выполнен, режим нельзя рекламировать как production-ready
или обещать «ни одной утечки».
